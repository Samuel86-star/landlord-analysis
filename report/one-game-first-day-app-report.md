# APP 端注册当天只玩 1 局用户分析报告

> 本报告基于 `data/one-game-first-day-app/` 下的 4 份查询结果，分析 APP 端注册当天只玩 1 局用户的共性特征。
>
> **分析时间段**：2026-03-02 至 2026-05-10
> **调整分段**：调整前 `2026-02-10` 至 `2026-04-20`；调整后 `2026-04-21` 至 `2026-05-20`
> **分析对象**：APP 端注册用户，排除首日登录日志缺失用户
> **主分析口径**：`1局用户` vs `2局及以上用户`

---

## 一、结论摘要

本期 APP 端注册用户共 `92,856` 人，其中注册当天 `0局用户` 为 `13,507` 人，占 `14.55%`；`1局用户` 为 `7,921` 人，占 `8.53%`；`2局及以上用户` 为 `71,428` 人，占 `76.92%`。在首日有对局用户中，`1局用户` 占 `9.98%`，整体规模稳定但仍有明确优化空间。

由于 `2026-04-21` 前后做过调整，后续结论应拆成调整前后两段解读。当前已提交数据只覆盖到 `2026-05-10`，因此调整后数据只是 `2026-04-21` 至 `2026-05-10` 的阶段性预览，完整评估还需要补跑 `2026-05-11` 至 `2026-05-20`。

`1局用户` 的核心问题更偏向 **首局体验后的停止**，不是单纯进入游戏前流失。最强证据是：`1局用户` 首局胜率仅 `49.82%`，而 `2局及以上用户` 首局胜率为 `76.84%`；`1局用户` 首局后低于房间门槛占比为 `49.96%`，约为 `2局及以上用户` 的 `2.17` 倍。

画像上，`1局用户` 在小米、360、咪咕、iOS 中明显偏高，客户端语言差异不明显。这里的判断应看“维度内 1局率”，而不是只看 `1局用户` 内部构成。体验上，主要集中在经典玩法 `12074` 和 `4484` 两个房间，表现为首局胜率低、净收益为负、首局后低于房间门槛占比高。

优先建议从 **首局保护、首局后补足资产、渠道质量分层** 三条线推进，而不是先看客户端语言问题。

## 三、1局用户画像共性

本章需要特别注意口径：原始查询里的 `one_game_share` 表示“某特征在 1局用户内部的构成占比”，不是“该特征用户中有多少人只玩 1 局”。因此判断某画像是否更容易只玩 1 局，应优先看 `1局用户 / (1局用户 + 2局及以上用户)`，并用整体基线 `9.98%` 作参照。

### 3.1 渠道分类

`1局用户` 在以下渠道分类中明显偏高：

| 渠道分类 | 1局用户 | 2局及以上用户 | 维度内1局率 | 相对整体基线 |
| ---- | ---- | ---- | ---- | ---- |
| 小米 | 75 | 313 | 19.33% | 1.94 倍 |
| 360 | 327 | 1,450 | 18.40% | 1.84 倍 |
| 咪咕 | 647 | 3,431 | 15.87% | 1.59 倍 |
| IOS | 673 | 4,443 | 13.15% | 1.32 倍 |

小米样本较小，优先级低于 360、咪咕、iOS。华为、荣耀、三星的维度内 1局率分别为 `8.44%`、`7.53%`、`7.40%`，低于整体基线，反而不偏向 1局用户。

### 3.2 平台和客户端语言

| 维度 | 取值 | 1局用户 | 2局及以上用户 | 维度内1局率 |
| ---- | ---- | ---- | ---- | ---- |
| 平台 | iOS | 673 | 4,443 | 13.15% |
| 平台 | Android | 7,248 | 66,985 | 9.76% |
| 客户端语言 | Cocos-Creator | 789 | 7,011 | 10.12% |
| 客户端语言 | Cocos-Lua | 7,130 | 64,397 | 9.97% |

平台上 iOS 明显高于整体基线和 Android。客户端语言几乎没有差异：Cocos-Creator 为 `10.12%`，Cocos-Lua 为 `9.97%`，都贴近整体基线 `9.98%`。因此当前数据不支持“某个客户端语言导致只玩 1 局”的判断。

### 3.3 首日登录次数

首日登录次数需要看维度内 1局率：

| 首日登录次数 | 1局用户 | 2局及以上用户 | 维度内1局率 |
| ---- | ---- | ---- | ---- |
| 1次 | 6,907 | 53,864 | 11.37% |
| 2-5次 | 969 | 17,055 | 5.38% |
| 5次以上 | 45 | 509 | 8.12% |

首日只登录 1 次的用户更容易只玩 1 局，但差异没有首局体验指标那么强。这个结果与“完成首局后直接离开”一致。

## 四、1局用户首局体验共性

### 4.1 整体首局体验对比

| 指标 | 1局用户 | 2局及以上用户 | 差异 |
| ---- | ---- | ---- | ---- |
| 首局胜率 | 49.82% | 76.84% | -27.02 个百分点 |
| 首局平均净收益 | -233 | 1,022 | 少 1,255 |
| 首局后低于房间门槛占比 | 49.96% | 23.01% | 约 2.17 倍 |
| 高倍局占比 | 47.61% | 49.04% | 基本接近 |
| 逃跑率 | 0.00% | 0.00% | 无差异 |

最关键的差异不是高倍局，也不是逃跑，而是 **首局胜率和首局后资产状态**。`1局用户` 接近一半在首局后低于房间门槛，这会直接削弱继续下一局的能力。

这里还需要补充一个更聚焦的下钻：**只看首局失败用户，比较“失败后停止”和“失败后继续第 2 局”的差异**。当前 4.1 的整体对比会同时混入“首局胜利后继续”的用户，因此它能说明 `1局用户` 的首局体验更差，但还不能完全解释“首局失败后，是什么因素决定用户是否继续”。

建议补跑以下维度：

- 首局失败后是否仍高于当前房间门槛。
- 首局失败后的剩余资产与房间门槛比值。
- 首局失败是否为地主。
- 首局失败是否高倍、炸弹、春天。
- 首局失败后到第 2 局的时间间隔。
- 第 2 局是否换玩法、换房间或降档。
- 第 2 局胜率和净收益，判断继续用户是否被后续体验拉回。

这组分析可以回答更具体的问题：首局失败用户里，继续第 2 局的人是否因为“还玩得起”、被引导到更合适房间，或者第 2 局获得了更好的反馈。

### 4.2 主要房间表现

`1局用户` 主要集中在经典玩法 `12074` 和 `4484`：

| 用户组 | 玩法 | 房间 | 用户数 | 首局胜率 | 首局净收益 | 低于门槛占比 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 1局 | 经典 | 12074 | 4,159 | 49.58% | -265 | 50.28% |
| 1局 | 经典 | 4484 | 3,403 | 48.99% | -289 | 50.87% |
| 2局及以上 | 经典 | 12074 | 36,325 | 75.61% | 990 | 24.34% |
| 2局及以上 | 经典 | 4484 | 31,477 | 77.33% | 1,066 | 22.56% |

这两个房间承担了大部分首局样本。差异非常集中：同样是经典房间，`1局用户` 首局胜率约 49%，而继续玩的用户首局胜率约 76%-77%。这更像首局保护或首局难度/经济反馈差异，而不是玩法选择本身的问题。

| 高风险组合 | 1局用户 | 2局及以上用户 | 相对差异 |
| ---- | ---- | ---- | ---- |
| 首局失败且低于房间门槛 | 49.96% | 23.01% | 2.17 倍 |
| 首局失败且高倍局 | 22.99% | 10.97% | 2.10 倍 |
| 首局失败且为地主 | 34.73% | 16.82% | 2.06 倍 |
| 高服务费压力且净亏损 | 49.40% | 23.01% | 2.15 倍 |
| 首日只登录 1 次 | 87.20% | 75.41% | 1.16 倍 |

高风险组合集中指向一个链路：用户首局失败，尤其是作为地主或高倍场景失败后，首局后资产不足或经济压力过高，然后停止继续游戏。

## 六、原因判断

### 6.1 更可能的原因

- **首局保护不足**：`1局用户` 首局胜率只有约 50%，而继续玩的用户首局胜率约 77%。如果新手首局本应有保护，这个差异需要重点核查。
- **首局后资产不足**：`1局用户` 首局后低于房间门槛占比接近 50%，说明很多用户不是单纯“不想玩”，而是继续体验成本变高。
- **渠道质量差异**：360、咪咕、iOS 的 `1局用户` lift 明显偏高，说明部分来源用户可能更容易浅尝即止。

### 6.2 不支持的原因

- **客户端语言问题**：Cocos-Lua 与 Cocos-Creator 的 lift 接近 1，没有明显差异。
- **逃跑问题**：两组逃跑率均为 0，不是主要解释。
- **高倍局单独解释**：高倍局占比在两组中接近，单看高倍不是根因；但“首局失败 + 高倍”是高风险组合。

## 七、产品与运营建议

### 7.1 首局保护优先

优先核查经典 `12074`、`4484` 两个房间的新手首局匹配和保护逻辑：

- 首局是否应该匹配机器人或低强度对手。
- 首局地主角色是否过多承担高方差风险。
- 首局失败用户是否有即时补偿或下一局引导。

### 7.2 首局后资产兜底

针对首局后低于房间门槛的用户，建议设计轻量兜底：

- 首局失败后补足到最低房间门槛以上。
- 首局失败且净亏损用户提示可继续的低门槛房间。
- 对高服务费压力用户降低首局后继续成本。

### 7.3 渠道分层治理

优先关注 360、咪咕、iOS：

- 对这些来源单独看 `1局用户` 的首局胜率、低于门槛占比和房间分布。
- 若渠道内体验指标相同但 1局占比更高，偏流量质量问题。
- 若渠道内首局体验更差，偏产品适配或新手保护覆盖问题。
