# APP 端注册当天只玩 1 局用户分析报告

> 本报告基于 `data/one-game-first-day-app/` 下的 8 份查询结果，分析 APP 端注册当天只玩 1 局用户的共性特征。
>
> **分析时间段**：2026-03-02 至 2026-05-20
> **调整分段**：调整前 `2026-02-10` 至 `2026-04-20`；调整后 `2026-04-21` 至 `2026-05-20`
> **分析对象**：APP 端注册用户，排除首日登录日志缺失用户
> **主分析口径**：`1局用户` vs `2局及以上用户`

---

## 一、结论摘要

本期 APP 端注册用户共 `105,992` 人，其中注册当天 `0局用户` 为 `14,986` 人，占 `14.14%`；`1局用户` 为 `8,979` 人，占 `8.47%`；`2局及以上用户` 为 `82,027` 人，占 `77.39%`。在首日有对局用户中，`1局用户` 占 `9.87%`，整体规模稳定但仍有明确优化空间。

由于 `2026-04-21` 前后做过调整，结论必须拆成调整前后两段解读。完整分段结果显示：调整后 `0局占比` 从 `15.65%` 降到 `12.01%`，`2局及以上占比` 从 `76.24%` 升到 `79.01%`，说明调整后进入对局和持续多局的整体表现变好；但有对局用户中的 `1局占比` 从 `9.62%` 升到 `10.20%`，说明“玩完首局就停”的问题没有同步改善。

`1局用户` 的核心问题更偏向 **首局体验后的停止**，不是单纯进入游戏前流失。最强证据是：`1局用户` 首局胜率为 `51.45%`，而 `2局及以上用户` 首局胜率为 `78.17%`；`1局用户` 首局后低于房间门槛占比为 `48.34%`，约为 `2局及以上用户` 的 `2.23` 倍。

画像上，`1局用户` 在小米、360、咪咕、iOS 中明显偏高，客户端语言差异不明显。这里的判断应看“维度内 1局率”，而不是只看 `1局用户` 内部构成。体验上，主要集中在经典玩法 `12074` 和 `4484` 两个房间，表现为首局胜率低、净收益为负、首局后低于房间门槛占比高。

另一个必须单独处理的异常是 **对局耗时悖论**：`1局用户` 首局平均耗时为 `234.8` 秒，是 `2局及以上用户` 的 `2.69` 倍。异常主要集中在 `4484` 和 `22039`：`4484` 的 1局用户首局耗时 `366.7` 秒，而多局用户仅 `87.3` 秒；`22039` 的 1局用户首局耗时 `544.4` 秒，而多局用户仅 `71.0` 秒。这不像普通牌局体验差异，更像特定房间、特定人群上的卡死、托管超时、断线重连挂起或匹配/客户端响应异常，需要研发日志验证。

经济容错模型进一步说明：首局失败后低于门槛并不是偶发结果，而是规则上高度必然。首局失败用户在经典 `12074`、`4484` 房间的首局前资产约 `3,000` 银子，服务费约 `350`，房间实际门槛约 `2,500`，平均失败安全边界只剩 `196` 至 `244` 银子，低于经典房 `250` 底分。也就是说，用户只要在经典初级房首局失败，几乎任何正常倍数都会低于门槛。

首局失败后继续行为的补充数据说明：无论停止还是继续，第 1 局失败后低于房间门槛的比例都接近 `100%`。继续第 2 局用户的主要差异不在首局亏损更轻，而在于其仍会进入下一局，并且第 2 局胜率达到 `58.29%`、平均净收益为 `74`。因此优先建议从 **首局失败后的续局引导、第二局正反馈、经济兜底、渠道质量分层** 四条线推进，而不是只看客户端语言问题。

## 三、1局用户画像共性

本章需要特别注意口径：原始查询里的 `one_game_share` 表示“某特征在 1局用户内部的构成占比”，不是“该特征用户中有多少人只玩 1 局”。因此判断某画像是否更容易只玩 1 局，应优先看 `1局用户 / (1局用户 + 2局及以上用户)`，并用整体基线 `9.87%` 作参照。

### 3.1 渠道分类

`1局用户` 在以下渠道分类中明显偏高：

| 渠道分类 | 1局用户 | 2局及以上用户 | 维度内1局率 | 相对整体基线 |
| ---- | ---- | ---- | ---- | ---- |
| 360 | 411 | 1,657 | 19.87% | 2.01 倍 |
| 小米 | 82 | 339 | 19.48% | 1.97 倍 |
| 咪咕 | 748 | 3,828 | 16.35% | 1.66 倍 |
| IOS | 769 | 5,333 | 12.60% | 1.28 倍 |

小米样本较小，优先级低于 360、咪咕、iOS。华为、荣耀、三星的维度内 1局率分别为 `8.42%`、`7.26%`、`7.22%`，低于整体基线，反而不偏向 1局用户。

### 3.2 平台和客户端语言

| 维度 | 取值 | 1局用户 | 2局及以上用户 | 维度内1局率 |
| ---- | ---- | ---- | ---- | ---- |
| 平台 | iOS | 769 | 5,333 | 12.60% |
| 平台 | Android | 8,210 | 76,694 | 9.67% |
| 客户端语言 | Cocos-Lua | 8,056 | 73,147 | 9.92% |
| 客户端语言 | Cocos-Creator | 921 | 8,857 | 9.42% |

平台上 iOS 明显高于整体基线和 Android。客户端语言几乎没有差异：Cocos-Lua 为 `9.92%`，Cocos-Creator 为 `9.42%`，都贴近整体基线 `9.87%`。因此当前数据不支持“某个客户端语言导致只玩 1 局”的判断。

### 3.3 首日登录次数

首日登录次数需要看维度内 1局率：

| 首日登录次数 | 1局用户 | 2局及以上用户 | 维度内1局率 |
| ---- | ---- | ---- | ---- |
| 1次 | 7,793 | 61,853 | 11.19% |
| 2-5次 | 1,140 | 19,584 | 5.50% |
| 5次以上 | 46 | 590 | 7.23% |

首日只登录 1 次的用户更容易只玩 1 局，但差异没有首局体验指标那么强。这个结果与“完成首局后直接离开”一致。

| 首局有炸弹占比 | 31.45% | 33.02% |
| 首局有春天占比 | 7.64% | 4.66% |

这个结果很关键：首局失败后是否继续，并不能简单用“首局失败后是否低于门槛”解释，因为两组低于门槛占比都接近 `100%`。继续用户与停止用户的首局亏损、门槛状态、高倍、地主占比也非常接近。更可能的差异在后续链路：继续用户平均约 `401` 秒进入第 2 局，第 2 局胜率 `58.29%` 且平均净收益转正。也就是说，失败后能否被顺利带到下一局，以及下一局是否给到正反馈，可能比首局失败本身更重要。

### 4.5 注册赠送与失败破产容错模型

在本次数据口径中，首局 `start_money` 即原始表 `olddeposit`，代表系统发放给玩家的注册赠送银子或新手指引资产。结合经典初级房固定服务费约 `350` 银子，可以用 `avg_fee_pressure` 反推首局前资产：

| 房间 | 用户组 | 服务费压力 | 反推首局前资产 |
| ---- | ---- | ---- | ---- |
| 12074 | 1局 | 11.41% | 约 3,067 银子 |
| 4484 | 1局 | 11.26% | 约 3,108 银子 |

因此 APP 端新用户注册赠送银子的基准线可近似视为 `3,000` 银子。最新经济容错模型进一步显示，经典 `12074`、`4484` 首局失败用户的房间实际门槛约为 `2,500` 银子，而不是 `1,000` 银子。按经典房服务费约 `350` 计算，首局失败前的安全边界约为：

```text
最大可承受亏损 = 3,000 - 350 - 2,500 = 150 银子
```

按实际数据看，`1局用户` 首局失败后在核心房间的平均安全边界如下：

| 房间 | 角色 | 用户数 | 首局前资产 | 房间门槛 | 失败安全边界 | 低于门槛占比 | 平均倍数 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 12074 | 地主 | 1,597 | 3,092 | 2,500 | 244 | 99.56% | 41.0 |
| 4484 | 地主 | 1,283 | 3,070 | 2,500 | 221 | 99.69% | 50.4 |
| 12074 | 农民 | 697 | 3,045 | 2,500 | 196 | 100.00% | 27.6 |
| 4484 | 农民 | 621 | 3,061 | 2,500 | 212 | 99.84% | 22.6 |

经典初级房底分为 `250`。由于平均安全边界已经低于 1 倍底分，农民只要正常失败就很容易低于门槛；地主失败还需要同时赔付两个农民，更是几乎必然跌破门槛。考虑到首局失败后停止用户中地主占比达到 `68.57%`，且失败后两组低于门槛比例都接近 `100%`，这说明“首局失败后破产锁定”并不是偶发现象，而是由初始资产、房间门槛、服务费和地主双倍赔付共同决定的系统性结果。

## 六、原因判断

### 6.1 更可能的原因

- **首局保护不足**：`1局用户` 首局胜率约 `51%`，而继续玩的用户首局胜率约 `78%`。如果新手首局本应有保护，这个差异需要重点核查。
- **调整后首局后停止问题未改善**：调整后整体 0局下降、多局上升，但有对局用户中的 1局占比升到 `10.20%`，且 1局用户首局胜率和门槛状态变差。
- **失败后续局链路不足**：首局失败后两组几乎都低于门槛，但继续用户能进入第 2 局并获得 `58.29%` 胜率和正净收益，说明失败后的续局引导和第 2 局反馈可能是关键杠杆。
- **特定房间技术卡点**：`4484` 和 `22039` 的 1局用户首局耗时分别达到 `366.7` 秒和 `544.4` 秒，但同房间多局用户仅为 `87.3` 秒和 `71.0` 秒。这不是正常牌局节奏，强烈指向客户端卡死、响应假死、断线重连挂起、匹配挂起或 AFK 托管超时等技术问题，需要结合客户端与服务端日志验证。
- **经济容错过低**：注册赠送资产约 `3,000` 银子，经典初级房服务费约 `350`、实际准入门槛约 `2,500`，首局失败安全边界仅约 `150` 至 `244` 银子，低于经典房 `250` 底分。该规则解释了为什么首局失败后低于门槛比例接近 `100%`。
- **渠道质量差异**：360、咪咕、iOS 的 `1局用户` 维度内 1局率明显偏高，说明部分来源用户可能更容易浅尝即止。

### 6.2 不支持的原因

- **客户端语言问题**：Cocos-Lua 与 Cocos-Creator 的 lift 接近 1，没有明显差异。
- **逃跑问题**：两组逃跑率均为 0，不是主要解释。
- **高倍局单独解释**：整体高倍局占比在两组中接近，且调整后高倍局占比下降但 1局问题没有改善，单看高倍不是根因；但“首局失败 + 高倍”仍是高风险组合。

## 七、产品与运营建议

### 7.1 首局保护优先

优先核查经典 `12074`、`4484` 两个房间的新手首局匹配和保护逻辑：

- 首局是否应该匹配机器人或低强度对手。
- 首局地主角色是否过多承担高方差风险。
- 首局失败用户是否有即时补偿或下一局引导。

### 7.2 失败后续局链路与资产兜底

首局失败后，停止用户和继续用户都几乎低于门槛，因此不能只做“门槛是否足够”的静态判断。建议重点优化失败后的续局链路：

- 首局失败后自动引导到可进入的低门槛房间。
- 首局失败后给出明确的下一局入口，减少中断。
- 对首局失败用户设计第 2 局保护或轻量补偿，保证第 2 局反馈不继续恶化。
- 监控首局失败到第 2 局的时间间隔，把超过 5 分钟未续局作为风险信号。
- 评估注册赠送银子从 `3,000` 提高到 `5,000` 的 A/B 实验。若经典房门槛保持 `2,500`、服务费约 `350`，首局最大可承受亏损可从约 `150` 提升到约 `2,150`，能显著提高地主和农民首局失败后的容错空间。
- 在首局失败结算页提供“去低门槛房间/练习场”的直接按钮，不要只弹出资产不足并把用户丢回大厅。
- 若不提高赠送额，也应评估对首局失败用户临时降低再入场门槛、免服务费续一局或发放一次性续局补贴。

### 7.3 调整后专项复盘

调整后多局占比提升，但 1局占比在有对局人群中略升。建议单独复盘调整内容：

- 调整是否主要改善了 0局进入问题，而没有覆盖首局后体验。
- 调整后首局胜率下降是否来自匹配、发牌、机器人策略或房间导流变化。
- 调整后高倍局下降但门槛不足上升，需核查经济门槛和初始资产配置是否同步变化。

### 7.4 研发专项：排查 4484 与 22039 房间耗时异常

建议客户端、匹配服务和战绩日志研发联合排查：

- 拉取 `4484` 和 `22039` 中 `timecost > 200秒` 且首日无后续对局的用户明细。
- 按渠道、客户端语言、版本、机型、网络状态、是否断线重连、是否托管、是否操作超时分组。
- 核查是否存在 UI 线程卡死、发牌/叫地主协议挂起、匹配状态未释放、断线重连循环、托管超时链路异常。
- 对比 `12074` 的同类日志，因为该房间 1局用户耗时相对正常，可作为健康对照组。

### 7.5 渠道分层治理

优先关注 360、咪咕、iOS：

- 对这些来源单独看 `1局用户` 的首局胜率、低于门槛占比和房间分布。
- 若渠道内体验指标相同但 1局占比更高，偏流量质量问题。
- 若渠道内首局体验更差，偏产品适配或新手保护覆盖问题。
