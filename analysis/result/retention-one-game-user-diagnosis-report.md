# 1 局用户留存问题诊断报告

> **目的**：整理 2026-06-30 围绕「只打 1 局就离开」用户的分析讨论过程、关键证据与产品启示，供团队评审与后续实验设计使用。
>
> **分析窗口**：`reg_date BETWEEN '2026-06-18' AND '2026-06-29'`
>
> **核心人群**：APP 端 `app_id = 1880053`，首日银子玩法 `silver_game_count = 1` 的新用户。
>
> **数据源**：`dws_app_firstday_game_stat`、`dws_ddz_firstday_game`、`dws_dq_app_daily_reg`、`dws_dq_silver_logs`
>
> **分析性质**：描述性诊断 + 产品假设形成；不宣称因果结论，后续需小流量 A/B 验证。

---

## 一、背景：为什么从 1 局用户切入

前序留存分析已确认：

- 已游戏玩家 D1/D7 留存偏低。
- 首日对局数与后续留存高度相关，且呈单调递增。
- 1 局用户是低留存群体，D7 留存极低。

讨论中最初的判断是：如果「让用户多玩几局」是强相关方向，那么可以考虑做简化版新手任务。但团队提出一个关键疑问：

> 如果用户第一局是赢的，为什么还会为了新手任务的银子奖励多玩几局？

因此，本轮分析的目标不是直接决定做任务，而是先回答：

```text
只打 1 局的人，到底是低质渠道、被虐走、经济破产、存银跑路，还是只是没有下一局理由？
```

---

## 二、诊断路径与假设

本轮依次验证以下假设：

| 顺序 | 假设 | 结论 |
| ---- | ---- | ---- |
| 1 | 1 局用户是否被低质渠道主导？ | 否。主流渠道为主，非脏流量。 |
| 2 | 1 局用户首局是否被虐走？ | 部分是。整体 70% 赢，但输家确实风险很高。 |
| 3 | 1 局用户是不是打完去操作保险箱？ | 否。保险箱操作率仅 1.16%。 |
| 4 | 1 局输家具体怎么输？ | 多数是 6-12x 新手保护局一把输到破产。 |
| 5 | 产品方向是否仍然是新手任务？ | 需要拆成两类：赢家用任务，输家用首败兜底。 |

## 三、渠道诊断：1 局不是低质流量问题

### 3.1 各渠道内部 1 局率

| 渠道 | 用户数 | 1 局率 | 相对大盘 lift | 10+局率 |
| ---- | ---- | ---- | ---- | ---- |
| 小米 | 60 | 25.00% | 3.61× | 21.67% |
| 咪咕 | 118 | 24.58% | 3.55× | 10.17% |
| vivo | 1,908 | 8.96% | 1.29× | 31.81% |
| OPPO | 1,560 | 8.46% | 1.22× | 35.32% |
| 官方(非CPS) | 1,456 | 6.94% | 1.00× | 36.26% |
| 三星 | 235 | 6.81% | 0.98× | 40.00% |
| IOS | 1,527 | 6.42% | 0.93× | 34.38% |
| 华为 | 2,759 | 6.38% | 0.92× | 36.90% |
| 荣耀 | 3,615 | 6.09% | 0.88× | 39.45% |
| 鸿蒙 | 1,322 | 4.77% | 0.69× | 38.80% |
| 360 | 306 | 3.27% | 0.47× | 5.88% |

### 3.2 结论

1 局用户不是被低质渠道主导。虽然咪咕 1 局率高（24.58%，3.55×），但体量小，只占 1 局用户很小一部分。1 局用户主体来自荣耀、华为、vivo、OPPO、IOS、官方等主流渠道。

**判断**：1 局问题主要是产品承接问题，而不是获客质量问题。

> 注：360 的 10+ 局率仅 5.88%，是另一类低质渠道信号，但它不是本轮「1 局用户」的主因。

## 四、首局画像：1 局用户整体不是牌差、漏保护或异常体验

### 4.1 1 局用户 vs 多局用户首局对照

| 特征 | 1 局-胜 | 1 局-负 | 10+ 局首局 |
| ---- | ---- | ---- | ---- |
| 人数 | 728 | 290 | 5,346 |
| 地主率 | 70.2% | 64.1% | 85.8% |
| 新手保护率 | 99.2% | 94.5% | 98.9% |
| 平均牌力 | 56.9 | 52.2 | 56.0 |
| 首局实际倍数 | 9.28 | 8.31 | 10.11 |
| 去脏后耗时 | 87s | 131s | 75s |
| 首局后银子 | 4,788 | 823 | 4,832 |
| 首局后破产率 | 0% | 46.6% | 2.7% |
| 单次会话率 | 90.8% | 90.7% | 64.1% |

### 4.2 被证伪的解释

| 假设 | 数据 | 结论 |
| ---- | ---- | ---- |
| 1 局用户被虐走 | 70% 首局获胜 | 仅解释输家，不能解释多数。 |
| 1 局用户牌差 | 牌力 56.9 / 52.2，与 10+局 56.0 接近 | 不成立。 |
| 1 局用户没被保护 | 胜者 99.2%、输者 94.5% 有新手保护 | 不成立。 |
| 1 局用户首局耗时异常 | 去脏后 87s / 131s，属于可解释范围 | 非主因。 |

### 4.3 关键分化点

1 局用户的最大差异是**单次会话率极高**：约 90.8%，而 10+ 局用户为 64.1%。

这意味着：

```text
1 局用户不是在首局前就低质，也不是首局体验全面崩坏。
他们大多只打开一次 App，打完第一局后没有进入第二局或其他系统。
```

## 五、保险箱诊断：不是存银/取银后离开

团队进一步提出：1 局用户是否可能在打完后操作保险箱（存银或取银），完成资产处置后离开？

### 5.1 保险箱操作识别

从 `dws_dq_silver_logs` 实际记录反查：

| op_id | op_name | 含义 |
| ---- | ---- | ---- |
| 300602 | 转入到保险箱 | 存入保险箱 |
| 300701 | 从保险箱转出 | 从保险箱取出 |

### 5.2 对局桶 × 保险箱操作率

| 对局桶 | 用户数 | 存入率 | 取出率 | 任一操作率 |
| ---- | ---- | ---- | ---- | ---- |
| **1 局** | 1,038 | **0.10%** | **1.06%** | **1.16%** |
| 2-5 局 | 3,422 | 4.03% | 8.33% | 8.62% |
| 6-10 局 | 3,510 | 4.39% | 8.09% | 11.08% |
| 10+ 局 | 5,346 | 4.94% | 16.57% | 17.81% |

### 5.3 结论

保险箱使用率随对局数单调上升，是深度用户行为。1 局用户几乎没有保险箱操作。

**证伪**：1 局用户不是「赢了后存银跑路」或「资产处置后离开」。

## 六、1 局输家深挖：真正的问题是一把输到破产

虽然 1 局用户中 70% 首局赢，但剩下 28% 首局输的用户风险极高。进一步分析这些输家怎么输。

### 6.1 1 局输家的输银分布

| 输的量级 | 人数 | 占比 | 平均输 | 末局后银子 | 破产率 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 小输（<-500） | 4 | 1.4% | -360 | 2,220 | 0% |
| 中输（-500~-1500） | 69 | 23.8% | -861 | 1,837 | 0% |
| **大输（-1500~-3000）** | **216** | **74.5%** | **-2,218** | **464** | **62.5%** |
| 巨输（-3000~-10000） | 1 | 0.3% | -5,310 | 2,620 | 0% |

### 6.2 结论

1 局输家不是「小输后心情不好」，而是被一局掏空。大部分输家开局约 3,000 银子，一局输掉 2,000+，末局后银子不足 1,000，无法顺畅进入第二局。

---

## 七、倍数深挖：6-12x 新手保护局是主要破产来源

### 7.1 1 局输家按倍数分布

| 倍数段 | shuffle_type | 人数 | 平均输 | 开局银子 | 末局银子 | 破产率 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 3-6x | 201 | 62 | -814 | 3,000 | 1,834 | 0% |
| **6-12x** | **201** | **206** | **-2,210** | **3,000** | **439** | **62.6%** |
| 6-12x | 0 | 7 | -1,857 | 3,286 | 1,079 | 42.9% |
| 12-24x | 201 | 5 | -960 | 3,000 | 1,620 | 0% |
| 24-48x | 201 | 1 | -2,580 | 3,000 | 0 | 100% |

### 7.2 关键结论

**1 局输家中，206 人（约 71%）属于同一种路径**：

```text
新手保护局（shuffle_type = 201）
→ 实际倍数 6-12x
→ 首局输了
→ 平均输 2,210 银子
→ 末局剩 439
→ 62.6% 直接破产
→ 打不了 / 不想打第二局
```

这说明新手保护机制给了好牌，但没有充分兜住「输局时的经济下限」。保护机制保护的是胜率，不是输局损失。

## 八、综合结论：1 局用户应拆成两个子问题

### 8.1 分群结论

| 子群 | 人数 | 占 1 局用户 | 核心问题 | 证据 |
| ---- | ---- | ---- | ---- | ---- |
| **1 局赢家** | 728 | 70% | 赢了但没有下一局理由 | 银子正常、牌力正常、保险箱无操作、单次会话率 90.8% |
| **1 局输家** | 290 | 28% | 一局被掏空，接近/直接破产 | 平均末局银子 823，破产率 46.6%，6-12x 保护局占主因 |

### 8.2 不应使用一个解释覆盖全部 1 局用户

- 对赢家：不是经济问题，而是缺少下一局理由。
- 对输家：不是单纯体验差，而是首败经济损失过大。

因此，产品方向也应拆成两条：

| 人群 | 产品方向 | 目的 |
| ---- | ---- | ---- |
| 1 局赢家 | 新手任务 / 进度条 / 第 2-3 局奖励 | 给「下一局理由」 |
| 1 局输家 | 首败兜底 / 首局输后补银 / 新手输局倍数封顶 | 避免第一局直接经济出局 |

## 九、产品建议（待 A/B 验证）

### 9.1 方案 A：会话内新手任务

**目标人群**：首局获胜但可能不续玩的用户。

**触发时机**：首局结算后立即展示。

**核心设计**：

```text
已完成 1/3 局，再打 2 局领取新手专属奖励
```

重点不是银子金额，而是「进度感」和「下一局理由」。奖励可考虑：

- 限定头像框 / 称号 / 道具
- 连续 3 局礼包
- 第二局、第三局逐步解锁奖励

### 9.2 方案 B：首败兜底

**目标人群**：首局失败且末局银子低于阈值的用户。

可选设计：

| 方案 | 说明 | 风险 |
| ---- | ---- | ---- |
| 首局输后补银到 3,000 | 最直接，确保能开第二局 | 可能增加银子投放 |
| 首局失败补偿券 | 文案上更像「再来一次」 | 需要新增道具/配置 |
| 新手前 N 局输局倍数封顶 | 从机制上避免一把清空 | 需要改对局结算或倍数机制 |
| 新手前 N 局最低剩余银保护 | 输多少都保留开下一局资本 | 需要经济系统支持 |

### 9.3 推荐先做小流量实验

建议灰度拆两个实验，不要混在一起：

| 实验 | 目标 | 主指标 | 护栏指标 |
| ---- | ---- | ---- | ---- |
| A：新手任务 | 降低 1 局赢家流失 | 1 局率下降、2+局率提升、D1/D3/D7 留存 | 首日逃跑率、付费率、银子通胀 |
| B：首败兜底 | 降低 1 局输家破产流失 | 首败后第二局进入率、1 局输家占比下降 | 银子投放、付费率、破产率 |

## 十、下一步建议

1. **先确认产品可实现范围**：能否做到首局结算后任务弹窗？能否做到首败补银或倍数封顶？
2. **优先做最小实验**：
   - A 方案最小版：首局结算页加 3 局任务进度，不改对局机制。
   - B 方案最小版：首局失败且银子 <1,000 时补到 3,000，提示「新手保护补给」。
3. **同步准备指标回收 SQL**：按实验组/对照组看 1 局率、2+局率、D1/D3/D7、付费和银子消耗。
