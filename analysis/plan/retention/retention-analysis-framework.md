# 留存分析框架：视角与相关指标

> 本文档提炼留存分析的核心视角、关键指标及其与留存的相关性规律，作为后续分析的速查手册。
>
> 基于 2026-06-11 重构后的数仓表结构更新。

---

## 框架概览

```text
输入层：新增用户数据
    ↓
分析视角：用户属性 / 投入度 / 胜负体验 / 经济状态
    ↓
指标层级：高相关性指标 / 中等相关性指标 / 背景指标
    ↓
输出层：高危信号组合 / 干预优先级
```

---

## 一、分析视角（四大维度）


| 视角       | 核心问题          | 分析子维度                                                      |
| -------- | ------------- | ---------------------------------------------------------- |
| **用户属性** | "谁"更容易留存/流失？  | 渠道分类、设备类型（iOS/Android）、客户端版本（Cocos-Lua/Cocos-Creator）、注册时段 |
| **投入度**  | "玩得多少"影响留存？   | 首日对局数、首日总时长、玩法数量、是否跨玩法                                     |
| **胜负体验** | "输赢感受"如何影响留存？ | 首日胜率、连胜/连败长度、首局胜负、角色胜率差异（地主/农民）、角色偏好、炸弹/春天数                |
| **经济状态** | "银子压力"是否驱动流失？ | 银子净变化、破产状态、高倍局输赢、携银与房间匹配度、房间底注门槛                           |

## 二、留存相关指标（影响力金字塔）

### 2.1 高相关性指标（直接影响留存）


| 指标 | 分组方式 | 留存规律（证据状态） | 数据来源表 |
| ---- | ---- | ---- | ---- |
| **首日对局数** | 0局/1局/2-5局/6-10局/10+局 | 留存随对局数**单调递增**，无最优区间、无疲劳拐点；0→50+局 D7 差 16.6 倍，1局用户次留最低（首局劝退）。已验证：[global §3.2](../../result/retention-global-report.md)、[protection §2.1](../../result/retention-protection-period-report.md) | `dws_app_silvergame_stat` + `dws_app_scoregame_stat` |
| **首日胜率** | <30%/30-50%/50-70%/70%+ | **倒 U 型**：30-50% 留存最优（D7≈15%），<30% 与 ≥70% 双低；<30% 被虐流失高危，≥70% 多为浅尝低对局用户。已验证：[global §3.4](../../result/retention-global-report.md)。注：30-50% 桶偏粗（Samuel 2026-06-17 提议改 10% 档位），待 `dws_app_firstday_game_stat` 宽表回填后细化 | `dws_app_silvergame_stat` |
| **连败长度** | 0-1/2-3/4-5/5+ | **已证伪**：控对局数后 1-50 局区间连败与留存无负相关或正相关，纯 engagement proxy；仅 50+局 ×5+连败 D7 骤降(22% vs 44%, n=104) 为窄 P1 信号。见 [复核报告](../../result/retention-recheck-lose-streak-bankruptcy-report.md) §一 | `dws_app_silvergame_stat` |
| **银子净变化** | 巨亏(<-5万)/大亏(-5万~-1万)/小亏(-1万~0)/小赚(0~1万)/大赚(1万~5万)/巨赚(>5万) | 留存与净变化**绝对值正相关**（倒置关联，重度用户代理变量），非"亏损低留存"；小亏/小赚（占71%）无显著差异。已验证：[global §3.8](../../result/retention-global-report.md) | `dws_app_silvergame_stat` |
| **是否破产** | 银子谷值≤最低房间门槛 | **已证伪**：改用严格末局定义(`silver_end_money<1k`)+控对局数后，1-50 局区间破产组留存仍持平或略高；50+局尾部破产 D7 略低但 n=114/58 不稳健。当前数据不足以验证破产→流失，建议沿用严格定义重新建模。见 [复核报告](../../result/retention-recheck-lose-streak-bankruptcy-report.md) §二 | `dws_app_silvergame_stat` |
| **高倍局输赢** | 仅赢高倍/仅输高倍/有赢有输 | 部分修正：仅输与仅赢高倍次留差仅 1.5pp，"经历过高倍局"本身才是强信号，无论赢输；非"输高倍高危/赢高倍提升"。已验证：[global §3.7](../../result/retention-global-report.md) | `dws_app_allgame_stat` |


### 2.2 中等相关性指标（需分场景分析）


| 指标          | 分组方式              | 留存规律                            | 数据来源表                     |
| ----------- | ----------------- | ------------------------------- | ------------------------- |
| **首日平均倍数**  | ≤6/6-12/12-24/24+ | 倒U型关系，12-24x留存最优（非越高越好）         | `dws_app_allgame_stat`    |
| **首局胜负**    | 胜/负               | 首局胜率预期偏高（新手配牌），首局负留存显著低         | `dws_ddz_firstday_game`   |
| **逃跑次数**    | 0/1/2/3+          | 逃跑反映挫败感，逃跑率>15%留存极低          | `dws_app_silvergame_stat` |
| **房间底注/门槛** | 极低/低/中/高          | 越高的底注破产风险越大，对新手留存压力越大           | `dws_app_allgame_stat`    |
| **角色偏好**    | 纯农民/偏好农民/均衡/偏好地主  | 地主体验方差大（大输大赢），偏好地主的用户留存与经济变化强绑定 | `dws_ddz_firstday_game`   |
| **玩法选择**    | 单玩法/多玩法           | 多玩法探索用户留存更高（兴趣广）                | `dws_app_gamemode_active` |


### 2.3 弱相关性/背景指标（区分用户类型）


| 指标            | 作用                        | 数据来源表                                              |
| ------------- | ------------------------- | -------------------------------------------------- |
| **渠道分类**      | 区分渠道质量，非产品问题              | `dws_dq_app_daily_reg` + `dq_channel_category_map` |
| **客户端版本**     | 识别稳定性差异（多次登录=崩溃信号）        | `dws_dq_app_daily_reg`                             |
| **注册时段**      | 区分用户画像（夜间玩家/白天玩家），时段本身无因果 | `dws_dq_app_daily_reg`                             |
| **炸弹数、春天发生率** | 游戏体验细节，需分玩法看（癞子天然高倍）      | `dws_app_allgame_stat`                             |

## 三、流失高危信号组合


| 组合特征 | 留存预期 | 优先级 | 备注 |
| ---- | ---- | ---- | ---- |
| **连败≥3 + 银子亏损 + 高倍局输** | D7 非<10%（证伪） | P2 | 已验证：D7 命中组 9.65%~23.79%，多数段 ≥ 同段基线，非灾难性低；D30 重度玩家(11-50局)较同段低 3-5pp，弱长期信号。见 [复核报告](../../result/retention-recheck-lose-streak-bankruptcy-report.md) §三 |
| **首局负 + 地主角色 + 高倍局** | 信号真但覆盖窄 | P1 | 已验证：1-5局段 D7=1.66%(基线1/3)、6-10局段 D7=4.88%(基线~半)；但 5月15天仅 248 人命中，覆盖窄非主力拦截点。见 [复核报告](../../result/retention-recheck-lose-streak-bankruptcy-report.md) §4.1 |
| **0局/1局 + 多次登录（≥3）** | 证据不足 | P2 | 已验证：多次登录在 0-1局群体内无额外预测力(0局段 D7 反更高、1局段 n=21 不稳健)。崩溃假设需走崩溃日志验证而非登录次数代理。见 [复核报告](../../result/retention-recheck-lose-streak-bankruptcy-report.md) §4.2 |
| **破产 + 不再对局** | 证伪 | — | 末局破产用户 D1 回归率不比同段非破产低（见 [复核报告](../../result/retention-recheck-lose-streak-bankruptcy-report.md) §二），"不再对局"不成立 |
| **胜率<30% + 对局数少（≤2）** | 弱信号 | P1 | 已验证：1局段 D7=1.90 vs 3.05(低1.15pp)，2局段几乎无差异。本质是对局数代理(≤2局<30%胜率≈首局输)，可干预点是首局体验。见 [复核报告](../../result/retention-recheck-lose-streak-bankruptcy-report.md) §4.3 |

## 四、分析路径建议

```text
Step 1: 留存概览 → 建立基线（渠道/设备/客户端分组留存）
  ↓
Step 2: 高相关性指标分组 → 确认规律（胜率/连败/破产/高倍局）
  ↓
Step 3: 多维交叉 → 定位高危组合（连败×破产×高倍输）
  ↓
Step 4: 专项下钻 → 找根因（1局用户对手构成/客户端稳定性）
  ↓
Step 5: 行动建议 → 优先级排序（P0保护机制/P1引导优化）
```

## 五、核心结论：影响留存的四条主线

> **聚焦窗口：D1-D7**。下表干预方向均以 D1-D7 实测证据为依据；D30 长期留存信号见 §2.1 与复核报告。

| 主线 | 核心指标（D1-D7 证据） | 产品干预方向 |
| ---- | ---- | ---- |
| **投入度线** | 首日对局数（最强信号，单调递增，0→50+ D7 差 16.6 倍）、首局胜负 | 首局体验强化（1局劝退是最大可改善群体）、新手任务推动越过 5/10 局门槛、新手礼包加厚 |
| **胜负情绪线** | 首日胜率（倒 U 型，30-50% 最优；<30% 被虐高危、≥70% 浅尝）、首局胜负 | 匹配系统确保新手首日胜率落入 30-60%；<30% 用户触发新手保护配牌；≥70% 低对局用户推送"再来几局" |
| **经济压力线** | 银子净变化绝对值（倒置关联，重度用户代理变量） | ⚠️ D1-D7 内经济因素非新手流失主因（小亏/小赚 71% 占比、留存无显著差异）；连败保护 / 破产兜底单项已证伪（见 §2.1），无 D1-D7 干预建议；高风险偏好重度用户（巨亏/巨赚）值得专项识别用于 D30 长期运营 |
| **稳定性线** | 多次登录（≥3 次=崩溃信号）、逃跑率 | 客户端崩溃修复、操作体验优化、逃跑罚没调整 |

> **已剔除的伪干预方向**（基于已证伪单项，避免误导）：连败打断机制（连败长度证伪）、破产兜底（破产证伪）、倍数上限限制（高倍输高危证伪）。

## 六、数仓表结构（2026-06 重构版）

### 6.1 账号域


| 表名                     | 粒度               | 说明                              |
| ---------------------- | ---------------- | ------------------------------- |
| `dws_dq_daily_reg`     | uid × reg_date   | 全平台用户注册信息                       |
| `dws_dq_daily_login`   | uid × login_date | 每日登录聚合（首次/最后/最频繁渠道、分端、app_code） |
| `dws_dq_app_daily_reg` | uid              | APP端注册用户宽表（预关联登录+渠道分类）          |


### 6.2 游戏域


| 表名                        | 粒度                            | 用途                                 |
| ------------------------- | ----------------------------- | ---------------------------------- |
| `dws_app_game_active`     | uid × dt × app_id             | **留存 flag 计算**（任意玩法有对局即活跃）         |
| `dws_app_gamemode_active` | uid × dt × app_id × play_mode | **同玩法留存 flag**（需在同一 play_mode 有对局） |
| `dws_app_silvergame_stat` | uid × dt                      | 银子玩法金流+参与度（play_mode 1,2,3,7）      |
| `dws_app_scoregame_stat`  | uid × dt                      | 积分玩法参与度+胜负（play_mode 4,5,6）        |
| `dws_app_allgame_stat`    | uid × dt × play_mode          | 全玩法体验分析（倍数/炸弹/胜率）                  |
| `dws_ddz_daily_game`      | resultguid × uid              | 经典斗地主对局明细（play_mode 1~6）           |
| `dws_ddz_firstday_game`   | resultguid × uid              | 经典斗地主首日对局明细（同字段，仅 reg_date = dt）   |
| `dws_crazyddz_daily_game` | resultguid × uid              | 疯狂斗地主对局明细（play_mode=7，多轮聚合）        |


### 6.3 表选用决策树

```text
需要留存 flag？
  ├── 整体留存（任意玩法） → dws_app_game_active
  └── 同玩法留存 → dws_app_gamemode_active
需要归因指标？
  ├── 银子金流 → dws_app_silvergame_stat
  ├── 积分参与度 → dws_app_scoregame_stat
  └── 玩法体验（倍数/炸弹） → dws_app_allgame_stat
需要用户属性？
  └── dws_dq_app_daily_reg（含渠道分类、客户端版本、设备类型）
```
