## 项目定位

本项目适合按三个方向维护：

- **AI 数据分析智能体**：理解分析问题、生成 SQL、查询 StarRocks、校验数据并形成结论。
- **斗地主发牌算法智能体**：执行牌型拆分、牌力评分、发牌与重洗，并通过仿真评估结果。
- **项目基础设施**：为两个方向提供安全、构建、测试、规范和运行环境。

其中，数据分析方向已经具备“工具执行链”的雏形；发牌算法方向当前更接近算法服务。只有补齐任务编排、工具调用、结果解释和反馈闭环后，后者才是完整意义上的智能体。

## Skill 策略

建议为两个业务方向各创建一个 project skill，但暂不为基础设施单独建 skill：

| Skill 候选 | 适用场景 | 核心价值 | 当前决策 |
| ---- | ---- | ---- | ---- |
| `data-analysis-agent` | 用户提出取数、指标分析或结论问题 | 固化知识检索、SQL 安全检查、执行、质检和结论模板 | 等待 5 至 10 个真实任务 |
| `dealing-algorithm-agent` | 用户要求调参、比较策略、验证公平性或同步实现 | 固化双语言同步、不变量检查、仿真与回归流程 | 等待至少 5 个真实任务记录 |
| `project-foundation` | 通用工程规范 | 与 `AGENTS.md`、CI 和脚本职责重叠 | 不创建 |

Skill 只保存稳定、重复出现的协作流程，不承载业务实现，也不复制完整知识库。确定性校验应留在代码和 CI 中，不能依赖模型记住规则。
