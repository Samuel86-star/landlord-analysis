## 二、背景与问题

项目已经具备数仓知识、SQL 规范、分析方案、查询工具和批量回填脚本，可以支持“生成 SQL、查询数据、形成分析”的人工协作流程。

当前流程还不能作为可靠的 AI 数据分析智能体直接自动执行，主要原因如下：

- 查询工具未强制拦截 DDL，关键安全规则只存在于文档。
- 回填可能把零行或 strict mode 回滚误判为成功。
- DELETE 与 INSERT 之间缺少已验证的恢复机制。
- 数据库凭据和传输方式不符合安全要求。
- 分析任务缺少统一的问题澄清、SQL 审查、结果质检和结论溯源流程。
- 家庭网络无法访问公司数仓，离线开发与线上联调必须明确分开。

## 三、目标与非目标

### 3.1 目标

- 将自然语言问题转换为口径明确、可执行、可验证的 SQL 分析任务。
- 在任何 SQL 提交前执行确定性安全检查。
- 对查询和回填结果执行最小数据质量检查，失败时停止而不是继续生成结论。
- 保存问题、口径、SQL、结果摘要、限制和生成时间，使结论可以追溯。
- 支持家庭网络下的离线开发，并将公司网络联调设为独立验收门槛。
- 在执行链稳定后，用 project skill 固化重复的交互流程。

### 3.2 非目标

- 不构建通用多智能体平台、工作流引擎或语义层。
- 不允许模型直接连接数据库或绕过 `ops/py/sr_exec.py`。
- 不允许脚本执行 DDL；DDL 继续由用户在 CloudBeaver 手动执行。
- 不让模型自行实现 SQL parser、统计计算或重试机制。
- 不在家庭网络环境宣称真实数仓查询、事务或权限验证已经通过。
- 不自动发布分析结论，也不自动修改生产表结构。

## 四、设计原则

1. **确定性控制优先**：安全校验、退出码、数据质检和重试由代码执行，不能只写在提示词中。
2. **DWS 优先**：查询优先使用 `dws_*_daily_game`，只有缺字段或排障时回退 raw，并在结果中说明原因。
3. **最小权限**：查询和写入凭据不进入仓库，账号权限按用途收窄。
4. **失败即停止**：SQL 检查、执行或质检任一失败时，不生成无依据结论，不继续下游任务。
5. **证据可追溯**：结论必须关联实际执行的 SQL、口径、时间范围和质量检查结果。
6. **分阶段验收**：离线测试通过不等于数仓集成通过，两者分别记录状态。

## 五、系统边界

### 5.1 模型负责

- 理解用户问题并识别缺失条件。
- 根据项目知识选择指标、表和分析方法。
- 生成或修改 SQL 草稿。
- 调用确定性检查与查询工具。
- 基于已通过质检的结果解释现象、限制和下一步。

### 5.2 代码与工具负责

- SQL 类型识别和 DDL 拦截。
- SQL 执行、超时、退出码和错误输出。
- 回填后的行数及业务断言。
- 数据结果的结构化保存与基础质量检查。
- 重试策略、日期处理和确定性格式转换。

### 5.3 用户负责

- 确认存在业务歧义的指标口径和分析范围。
- 在 CloudBeaver 手动执行经过确认的 DDL。
- 提供或配置不入库的数据库凭据。
- 审批生产写入、恢复操作和最终业务结论。

## 六、任务类型

智能体首先将请求归入以下一种类型；无法确定时先澄清，不执行 SQL。

| 类型 | 典型输入 | 是否允许自动查询 | 是否允许写入 |
| ---- | ---- | ---- | ---- |
| 临时查询 | 查询某指标、分组或趋势 | 是 | 否 |
| 分析方案 | 设计指标、拆解问题、生成 SQL | 用户确认后 | 否 |
| 结果解释 | 解读已有查询结果 | 不一定需要 | 否 |
| 数据回填 | 更新指定日期的聚合表 | 仅在公司网络且显式授权后 | 是 |
| DDL 需求 | 建表、改表、删表或截断表 | 否 | 脚本禁止 |

## 七、端到端流程

### 7.1 问题澄清

执行前形成最小任务契约：

- 目标指标与业务问题。
- 时间范围、时间粒度和时区。
- 用户、对局或房间等统计粒度。
- 过滤条件、玩法和房间等级。
- 分母、去重口径和对照组。
- 期望产物：临时结果、分析方案或正式结论。

只有影响结果的歧义需要询问用户；可以从项目知识中确定的内容直接引用并说明。

### 7.2 知识检索

按以下顺序读取最小必要上下文：

1. `SQL_STYLE.md` 与项目 `AGENTS.md`。
2. `docs/knowledge/` 中对应的表、字段、房间和口径文档。
3. `starrocks/` 中对应表文档。
4. `docs/lessons/` 中相关 SQL 模式。
5. `docs/analysis/` 中与当前问题直接相关的方案和结果。

不得为了“补充上下文”无差别加载全部文档。

### 7.3 SQL 生成与静态检查

SQL 提交前必须通过以下检查：

- 拒绝 `CREATE`、`ALTER`、`DROP`、`TRUNCATE` 等 DDL。
- 默认拒绝无法明确判断类型的多语句输入。
- 分区表必须包含时间或分区范围。
- 优先 DWS；回退 raw 时记录原因。
- 房间等级和玩法读取 `tcy_temp.dq_game_room_config`，不得由底分或 `play_mode` 反推。
- 用户数使用 `COUNT(DISTINCT uid)`。
- 百分比除法使用 `NULLIF(denominator, 0)`。
- 表和 CTE 使用有意义的别名。

脚本负责可确定识别的规则；模型负责不能可靠静态判断的口径审阅。任何阻断项都应给出明确原因和修改建议。

### 7.4 执行

- 临时 SQL 保存到 `ops/py/tmp/`。
- 查询统一通过 `ops/py/sr_exec.py -f <file>` 执行。
- 凭据从环境变量或不入库的本地配置读取，缺失时立即失败。
- 日志不得输出 credential、session token 或完整认证响应。
- 家庭网络无法连接时，任务状态标记为“等待公司网络联调”，不能伪造或推测结果。

### 7.5 结果质检

查询成功不等于分析可用。生成结论前至少检查：

- 是否返回数据，零行是否符合任务预期。
- 时间覆盖是否完整。
- 样本量与分母是否足以支持结论。
- 关键字段的空值、重复和异常范围。
- 汇总值与明细或已有基线是否存在明显冲突。

回填任务还必须执行任务定义的行数或业务断言。断言失败时返回非零退出码，并停止后续任务。

### 7.6 结论与留档

正式结论至少包含：

- 业务问题与结论摘要。
- 指标口径、时间范围和过滤条件。
- 数据来源与实际执行 SQL 的位置。
- 样本量和质量检查结果。
- 已知限制、异常和不能回答的部分。
- 生成时间；数据可能变化时记录数据截至时间。

正式方案和结论沿用 `docs/analysis/plan/` 与 `docs/analysis/result/`。临时查询不进入正式目录。

## 八、失败处理与恢复

| 失败阶段 | 行为 | 是否继续 |
| ---- | ---- | ---- |
| 口径不明确 | 请求用户确认关键歧义 | 否 |
| SQL 静态检查失败 | 返回命中规则与修改建议 | 否 |
| 网络不可达 | 保存 SQL 和待验证项 | 否 |
| 查询执行失败 | 保留错误类型与安全日志 | 否 |
| 查询返回零行 | 按任务是否允许空结果判定 | 默认否 |
| 结果质检失败 | 输出异常证据，不生成业务结论 | 否 |
| 回填写入失败 | 阻止下游任务，执行已验证的恢复策略 | 否 |

在确认 StarRocks 与 CloudBeaver 的事务能力前，不承诺 DELETE 与 INSERT 原子化。联调结论必须选择并验证以下一种策略：同会话事务、暂存后替换，或可证明安全的补偿恢复。

## 九、网络环境与验收边界

### 9.1 家庭网络可完成

- DDL 拦截与多语句策略。
- 零行回填失败和退出码逻辑。
- 凭据配置化及敏感日志清理。
- SQL 中防零除规则的机械修正。
- 使用 mock 或假执行器测试成功、失败、零行和网络异常。
- Skill 文档草案和分析产物模板。

这些工作只能标记为“离线验证通过”。

### 9.2 公司网络必须完成

- 真实 CloudBeaver 登录、查询和错误响应验证。
- HTTPS 可用性、账号权限和凭据轮换确认。
- StarRocks 事务或替代恢复方案验证。
- 真实 DWS 查询、分区过滤和结果质检。
- 回填失败、零行和恢复演练。

只有本节全部通过，数据执行能力才能标记为“集成验证通过”。

## 十、Skill 设计

### 10.1 创建时机

满足以下条件后创建 project skill：

- DDL 拦截和凭据隔离已完成。
- 查询失败与零行结果能被确定性识别。
- 至少一次公司网络端到端查询通过。
- 分析方案和结果的保存位置已经稳定。

### 10.2 Skill 最小职责

拟使用名称：`data-analysis-agent`。

Skill 只编排以下稳定流程：

1. 分类任务并形成最小任务契约。
2. 按优先级读取项目知识。
3. 生成 SQL 并执行项目红线检查。
4. 通过唯一工具入口执行查询。
5. 检查结果质量并生成可追溯结论。
6. 根据产物类型保存到现有目录。

### 10.3 Skill 禁止承载

- 数据库凭据和网络地址。
- 表结构、指标定义和房间映射的复制文本。
- SQL parser、重试、日期计算和数据质检算法。
- 绕过 DDL 禁令或查询工具的备用执行方式。
- 未经验证的事务或恢复承诺。

首版只创建一个 `SKILL.md` 并引用现有规范，不增加脚本。完成 5 至 10 个真实任务后，只有稳定重复的人工检查仍造成错误时，才增加窄职责检查脚本。

## 十一、分阶段交付

### 阶段 A：离线安全修复

- 移除代码中的凭据并改为私密配置。
- 在查询入口强制拒绝 DDL。
- 修复零行误判和失败退出码。
- 修正已发现的危险除法。
- 增加覆盖核心分支的最小自动化测试。

**完成定义**：本地测试通过，代码审查确认所有安全控制由确定性代码执行；状态记录为“离线验证通过”。

### 阶段 B：公司网络集成验证

- 轮换凭据并验证安全连接。
- 验证真实查询、错误和超时行为。
- 确认并演练回填恢复策略。
- 运行代表性 DWS 查询和回填任务。

**完成定义**：查询、回填、失败和恢复场景均有实际记录；状态记录为“集成验证通过”。

### 阶段 C：智能体分析闭环

- 固化任务契约、结果质检和结论格式。
- 选取 5 至 10 个真实问题建立回归任务集。
- 验证每项结论都能追溯到 SQL 和口径。

**完成定义**：回归任务均通过安全检查和质检，失败场景不会生成无依据结论。

### 阶段 D：Project Skill

- 创建最小 `data-analysis-agent` skill。
- 引用项目规范和现有工具，不复制业务知识。
- 用阶段 C 的任务验证触发、流程和输出。

**完成定义**：Skill 能稳定执行既有流程，且移除 Skill 后底层安全控制仍然有效。

## 十二、验收标准

### 12.1 功能验收

- 能把分析请求归类并形成包含指标、时间、粒度和过滤条件的任务契约。
- 能生成符合项目 SQL 红线的查询并通过唯一入口执行。
- 能区分查询成功、零行、执行失败、网络不可达和质检失败。
- 只有质检通过的数据才能形成正式分析结论。
- 正式结论包含可定位的 SQL、口径、样本量、限制和数据时间。

### 12.2 安全验收

- 仓库与日志不包含可重放凭据。
- `sr_exec.py` 无法执行 DDL。
- 家庭网络下不会绕过网络限制或伪造数仓结果。
- 未经显式授权不会执行数据回填。
- 回填失败时不会继续下游任务。

### 12.3 测试验收

- 本地测试覆盖 DDL、注释前缀、多语句、零行、执行失败和允许空结果。
- 公司网络测试覆盖登录、查询、超时、权限拒绝、回填和恢复。
- 真实回归任务覆盖临时查询、分析方案、结果解释和数据回填。
- 每次验收明确记录“离线验证”或“集成验证”，两者不得混用。

## 十三、实施约束

- 优先修改现有公共入口，不在每个批处理脚本重复增加保护。
- 不新增第三方依赖，除非标准库无法满足且有实测必要。
- 不在本 Spec 内确定未经公司网络验证的事务方案。
- 任何 DDL 继续由用户在 CloudBeaver 手动执行。
- 本 Spec 通过评审后再编写实施计划，不直接以章节顺序代替开发任务拆解。
