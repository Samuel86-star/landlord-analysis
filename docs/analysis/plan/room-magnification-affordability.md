# 经典玩法房间倍数兑现率分析框架

## 背景

玩家对局中存在**理论倍数**（`magnification`，由叫分/炸弹/加倍等倍率链完整乘积）和**实际倍数**（`real_magnification = ABS(game_outcome_money) / room_base`，实际输赢除以底分）的差异。这个差异反映了"理论上该输赢多少"与"对手余额实际能付多少"之间的鸿沟，直接影响玩家体验。

本文档通过对顶级房（底分 4,000）的完整拆解，提炼出一套可复用的分析框架，用于评估各底分档房间的倍数兑现健康度。

> 分析时间窗口：2026-06-15 ~ 2026-07-14（近 30 天）
> 数据源：`tcy_temp.dws_ddz_daily_game`，过滤 `game_id = 53 AND play_mode = 1 AND robot != 1`

---

## 核心概念

### 1. 兑现率（Realization Rate）

```
兑现率 = AVG(real_magnification) / AVG(magnification)
```

- 兑现率 = 1.0：理论倍数完全兑现，无破产截断
- 兑现率 < 1.0：部分对局因余额不足，实际输赢小于理论值

### 2. 可扛倍数（Affordable Magnification）

玩家余额能承受的最大倍数，超过即发生破产截断：

```
农民可扛 = (start_money − room_fee) / room_base
地主可扛 = (start_money − room_fee) / (2 × room_base)   ← 瓶颈
```

地主需同时支付 2 个农民，可扛倍数是农民的一半，**地主端是整个房间的瓶颈**。

### 3. 压降来源

压降发生在**理论倍数 > 玩家可扛倍数**的对局中。具体拆为两个方向：

- **输钱方余额不足**：输家破产，赢家只能收到输家余额上限 → 双方 `real_magnification` 均被截断
- **赢钱方被对手余额限制**：对手余额不够付理论输赢 → 赢家实际收入低于理论值

## 分析步骤

### Step 1：理论倍数分布

拉取目标房间的理论倍数（`magnification`）分位数和分布表，了解倍数水位。

```sql
SELECT magnification, COUNT(*) AS cnt, ...
FROM tcy_temp.dws_ddz_daily_game
WHERE ... room_base = TARGET ...
GROUP BY magnification
```

关键指标：P25 / P50 / P75 / P85 / P90 / P95 / P99、192+ 占比。

### Step 2：实际倍数分布

同样分位数 + 分布表，与 Step 1 对比，定位压降发生在哪个分位区间。

### Step 3：输赢拆分

按 `result_id`（赢/输/平）分别计算兑现率：

```sql
GROUP BY role, result_id
```

- 农民赢 → 兑现率受**地主余额**约束
- 农民输 → 兑现率受**农民自身余额**约束
- 地主赢 → 兑现率受**农民余额**约束
- 地主输 → 兑现率受**地主自身余额**约束

### Step 4：玩家携银分布

拉取玩家入场时的 `start_money` 分位数，计算各分位对应的可扛倍数。

```sql
-- 按玩家维度（避免重复计数）
SELECT uid, MAX(start_money) AS max_money FROM ...
GROUP BY uid
```

### Step 5：高倍局地主余额分布

针对超出可扛倍数的理论倍数档位，看这些对局中**瓶颈方**的余额分布——到底多少人付得起、多少人付不起。

```sql
WHERE role = 1 AND magnification >= 临界倍数
SELECT magnification, PERCENTILE(start_money, ...) ...
```

### Step 6：参数调整模拟

评估不同调整方案的代价：

- **提入场下限** → 提高可扛倍数，但筛掉余额不足的玩家
- **降底分** → 提高可扛倍数比例，但改变房间定位
- **降底分 + 提下限** → 联动调，兼顾覆盖和留存

## 案例：底分 4,000 房间

### 房间参数

| 参数 | 值 |
| ---- | ---- |
| 底分（room_base） | 4,000 |
| 入场下限 | 130,000 |
| 入场上限 | 20 亿（≈无上限） |
| 服务费（room_fee） | 7,200 |
| 地主可扛（按下限算） | (130,000 − 7,200) / 8,000 = **15.4×** |

### Step 1-2：理论 vs 实际倍数

| 分位 | 地主理论 | 地主实际 | 农民理论 | 农民实际 |
| ---- | -------- | -------- | -------- | -------- |
| P25 | 6 | 6 | 3 | 3 |
| P35 | 12 | 12 | 6 | 6 |
| P50 | 12 | 12 | 6 | 6 |
| P75 | 24 | 24 | 12 | 12 |
| P85 | 48 | **31.2** | 24 | **15.4** |
| P90 | 48 | 48 | 24 | 24 |
| P95 | 96 | 48 | 48 | 24 |
| P99 | 192 | **96** | 96 | **48** |

P75（24×）以下零压降，P85 开始出现裂口。192+ 极端值仅占 1.9%（地主）和 0.5%（农民）。

### Step 3：输赢拆分兑现率

| 角色 | 结果 | 理论 | 实际 | 兑现率 |
| ---- | ---- | ---- | ---- | ------ |
| 地主 | 赢 | 25.0 | 21.8 | 0.87 |
| 地主 | 输 | 26.8 | 19.4 | 0.72 |
| 农民 | 赢 | 12.5 | 9.8 | 0.78 |
| 农民 | 输 | 12.2 | 10.2 | 0.84 |

去掉 192+ 极端值后（覆盖 99% 对局）：

| 角色 | 结果 | 理论 | 实际 | 兑现率 |
| ---- | ---- | ---- | ---- | ------ |
| 地主 | 赢 | 21.7 | 20.5 | 0.94 |
| 地主 | 输 | 18.8 | 17.4 | 0.93 |
| 农民 | 赢 | 10.8 | 9.5 | 0.88 |
| 农民 | 输 | 11.4 | 10.1 | 0.89 |

99% 正常对局兑现率 **88-94%**，仅 192+ 极端尾端拉低整体。

### Step 4：玩家携银分布

| 分位 | 地主携银 | 农民携银 | 地主可扛 |
| ---- | -------- | -------- | -------- |
| P10 | 142,105 | 146,800 | 16.9× |
| P25 | 210,797 | 220,050 | 25.4× |
| P35 | 263,898 | 268,596 | 32.1× |
| P50 | 360,166 | 373,230 | 44.1× |
| P75 | 791,390 | 804,055 | 98.0× |
| P90 | 1,526,008 | 1,592,525 | 189.9× |
| P95 | 2,227,417 | 2,529,639 | 277.5× |
| P99 | 5,160,522 | 5,302,445 | 644.2× |

P50 地主可扛 44.1×，已覆盖 P75 理论（24×）；P75 地主可扛 98×，覆盖 P95 理论（96×）。瓶颈集中在 P25 以下群体。

### Step 5：48×+ 高倍局地主余额

| 理论倍数 | 对局数 | P25 地主 | P50 地主 | 付不起比例 | 地主需付 |
| -------- | ------ | -------- | -------- | ---------- | -------- |
| 48 | 1,222 | 21.7万 | **38.1万** | 51.6% | 38.4万 |
| 96 | 508 | 22.0万 | 36.2万 | 74.4% | 76.8万 |
| 192 | 161 | 21.5万 | 36.5万 | 89.4% | 153.6万 |

48× 局中 P50 地主携银 38.1 万，需付 38.4 万，差仅 3,000——中位地主几乎足额。截断集中在 P25 以下（携银 21.7 万，缺口 43%）。

### 压降全景还原

```
84% 对局（≤24×）   ：零压降
10% 对局（48×）    ：中位地主基本扛得住，P25 以下崩
 4% 对局（96×）    ：普遍截断
 2% 对局（192×+）  ：严重截断，但样本极小
```

### Step 6：调整模拟

| 方案 | 底分 | 下限 | 地主扛 | 玩家留存 | 覆盖 |
| ---- | ---- | ---- | ------ | -------- | ---- |
| 当前 | 4,000 | 13万 | 15.4× | 100% | P50 |
| 仅降底分 | 2,500 | 13万 | 25.2× | 100% | P75（84%） |
| 联动调 | 2,500 | 20万 | 39.2× | 50.8% | P75（84%） |
| 提下限 | 4,000 | 40万 | 49.1× | 20.1% | P85（94%） |
| 覆盖 48× | 2,500 | 24.4万 | 48.0× | 38.8% | P85（94%） |

## 提炼：房间倍数健康度分析因子

### 因子 1：底分承载比

```
承载比 = (入场下限 − 服务费) / 底分
```

含义：按下限入场时，**农民**能扛多少倍。地主扛 = 承载比 / 2。

承载比越高，破产截断越少。4,000 底分房承载比 = 30.7，属所有经典房中最高。

### 因子 2：理论倍数水位

该房间实际发生的倍数分布（P50/P75/P85/P95/P99）。与承载比对比：

```
覆盖健康度 = 承载比 / 目标分位理论倍数（地主扛 = 承载比 / 2 / 目标分位）
```

> 以地主扛为准，因为地主是支付瓶颈。

### 因子 3：瓶颈方余额分布

按瓶颈角色（地主）的 `start_money` 分布，计算各分位可扛倍数，叠加理论倍数分布得出各分位的覆盖缺口。

### 因子 4：高倍局余额匹配度

在理论倍数 ≥ 承载比的局中，瓶颈方的实际余额分布。如果 P50 瓶颈方能扛住，则截断仅影响少数低余额玩家——属于结构性健康。

### 因子 5：调整代价

| 调整手段 | 直接影响 | 副作用 |
| -------- | -------- | ------ |
| ↑ 入场下限 | 提高承载比 | 筛掉低余额玩家 → 匹配池缩小 |
| ↓ 底分 | 提高承载比 | 改变房间定位（降级） |
| ↓ 底分 + ↑ 下限 | 联动提承载比 | 两者副作用叠加需精细平衡 |

### 判断矩阵

| 承载比 vs 理论水位 | 瓶颈方 P50 可扛 | 判断 |
| ------------------ | --------------- | ---- |
| 承载比 ≥ P85 | — | 健康，不动 |
| 承载比覆盖 P50-P75 | P50 能扛 P85 | 可接受，尾端截断属正常筛选 |
| 承载比覆盖 P50-P75 | P50 扛不住 P85 | 需调参 |
| 承载比 < P50 | — | 严重不健康，必须调 |

---

## 结论

4,000 底分房属于第一档：承载比覆盖 P75，P50 地主余额能扛 P85（48×），尾端截断发生在 P25 以下低余额玩家和 96×+ 极端高倍局。**不调参**。

核心逻辑：截断不是 bug，是对余额不足玩家的软性保护——付不起的钱本来就不会出现。硬提门槛是替玩家做选择，代价远大于收益。
