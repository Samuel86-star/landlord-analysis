# old2/Type0 发牌做牌模拟器

> ⚠️ **精确度警示（2026-08-05）**：本模拟器用**贪心拆牌**近似，炸弹率等概率数字与线上有偏差。
> **精确概率请用 1:1 剥离线上 C++ 的独立模拟器 [`extracted/harness.cpp`](extracted/README.md)**（MSVC/g++ 编译，递归最优拆牌，线上真值）。
> 本脚本仍可用于**快速的跨配置方向性扫描**（相对快慢可信），但不要拿它的绝对数字做上线决策。

> `old2_type0_sim.py` —— 把线上经典房 `old2`/Type0 的发牌做牌逻辑用 Python 1:1 复刻，
> 用来**快速模拟、量化各种改法的效果**，不需要 C++ 编译环境，**Python 3 开箱即用**。
> 适用：产品/运营/分析快速评估"做牌调整后，玩家手牌会变成什么样"。

## 一、快速开始

```bash
# ★推荐：目标组合（更好打）—— 控制连贯菜单 + 做牌 7 张（bmn=10）
py -3 old2_type0_sim.py run --fix control-flow --bmn 10 --n 20000

# 扫描所有改法对比（默认 bmn=12）
py -3 old2_type0_sim.py sweep --n 10000

# 扫描所有改法在 bmn=10 下的对比
py -3 old2_type0_sim.py sweep --bmn 10 --n 10000

# 看某个改法的牌型构成
py -3 old2_type0_sim.py structure --fix control-flow --bmn 10

# 跑内置测试（机制验证 + bug 复现 + 采样）
py -3 old2_type0_sim.py test

# 看帮助
py -3 old2_type0_sim.py
```

> 所有命令支持 `--seed`（固定随机种子，结果可复现、改法间可比）。

## 二、模拟场景

固定为**经典初级房新手保护**形态（线上 ~99% 走这个）：

- 1 真人 + 2 机器人；
- **真人为庄（FirstChair）**，两个机器人为闲（OtherChair）；
- 做牌配置 = `makedeal.json` 的 `old2`（`BeginMakeNum=12`、各 `First/OtherChair*` 阈值、`BigCardsTo=2`）；
- Type0 流程：洗牌 → 前 N 张固定发 → 体检（手数/炸弹/大牌）→ `DoMakeDeal` 五轮六步菜单补牌 → 填空。

> 想模拟其它形态（多真人、不优待真人等），需改 `deal()` 的 `player_types` / `is_fix_banker` 参数（见代码）。

## 三、改法清单（`--fix`）

| `--fix` | 含义 | 是否动代码 |
|---|---|---|
| `baseline` | 现状（含 bug，全菜单）——**改前基线** | — |
| `no-bomb` | 去掉 `MatchBomb`（不主动凑炸弹） | 改代码 |
| `bomb-last` | `MatchBomb` 降到菜单最后 | 改代码 |
| **`control-flow`** | **控制连贯（2王,顺,连对,三,对,炸）★推荐** | 改代码 |
| `control-flow-nobomb` | 控制连贯去炸（2王,顺,连对,三,对） | 改代码 |
| `fix-bug` | 修"第二轮无条件做牌"bug | 改代码 |
| `fix-bug-no-bomb` | 修 bug + 去 `MatchBomb` | 改代码 |

> ⚠️ `old2`/Type0 下，`makedeal.json` 能调的只有 `BeginMakeNum`、6 个阈值、`BigCardsTo`；
> **做牌菜单顺序（含凑炸的 `MatchBomb`）和那个 bug 是代码写死的，配置改不了**。所以降炸弹的改法都得改代码。

## 四、关键参数 `--bmn`

`--bmn` = `BeginMakeNum`：**前 N 张纯随机固定发，从第 N+1 张开始做牌**。默认 12（线上现状）。

- N 越小 → 做牌范围越大 → 手数越低（越好打），但牌被干预越多、越偏离自然；
- N 越大 → 越贴近自然发牌，但手数升高。

`control-flow` / `control-flow-nobomb` 菜单下，bmn 在 10~14 之间炸弹都很稳（0.13~0.20），所以 bmn 主要用来调"好打 vs 自然"的权衡。

## 五、推荐组合（二维扫描结论）

| 目标 | `--fix` | `--bmn` | 炸弹 | 手数 | 庄闲差 | 说明 |
|---|---|---|---|---|---|---|
| **更好打（★推荐）** | `control-flow` | **10** | 0.195 | **5.84** | 0.025 | 做牌 7 张，手数最低之一，炸弹仍近自然 |
| 最小改动 | `control-flow` | 12 | 0.155 | 6.27 | 0.025 | 只改菜单，bmn 不动，炸弹砍 63% |
| 最低炸（无爽点） | `control-flow-nobomb` | 12 | 0.133 | 6.31 | 0.016 | 最均衡、最低炸，但没炸弹 |
| 现状（对照） | `baseline` | 12 | 0.42 | 6.08 | 0.033 | 改前基线 |

**核心规律**（来自 `BeginMakeNum × 菜单` 二维扫描）：
1. **菜单比 bmn 重要**：只要菜单对了（炸垫后/去炸），bmn 从 8 到 14 炸弹都稳在 0.13~0.34；baseline 菜单才会随 bmn 暴涨（0.30~0.81）。
2. **2 王放最前** → 庄闲炸弹均衡；2 王放后 → 闲家炸弹偏多。
3. **连贯组合（顺/连对/三）靠前** → 手数更低（更好打）；**对子别优先**（会拆连贯）。

## 六、输出指标怎么看

| 指标 | 含义 | 怎么判断好坏 |
|---|---|---|
| **炸弹** | 单家平均持有炸弹数（4 张同点 + 王炸） | 越接近"纯随机 ≈ 0.19"越自然；现状 0.42（翻倍） |
| **手数** | 单家平均几手能出完（贪心拆牌估计） | **越少越好打**；纯随机 7.50 |
| **大牌** | 单家平均持有 2/王 张数 | 控制力；做牌不改变总量（≈1.89） |
| **庄炸/闲炸** | 庄（真人）/闲（机器人）的炸弹均值 | 看庄家优待程度、庄闲是否均衡 |

`structure` 的牌型构成：`rocket` 王炸 / `bomb` 炸弹 / `plane` 飞机 / `seq_pair` 连对 / `straight` 顺子 / `triple` 三张 / `pair` 对子 / `single` 单牌。**连贯组合多、单牌少 = 手感顺**。

## 七、依赖与定位

- **依赖**：Python 3 标准库（`random`/`argparse`），无第三方包。
- **定位**：1:1 复刻线上 `old2`/Type0（含已知 bug）的**研究用模拟器**，非生产代码。
- **参照源**：同目录 `previous/`（线上发牌代码副本 + `makedeal.json`），便于核对一致性。
